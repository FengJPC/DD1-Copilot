# 探险闭环实机验收

日期：2026-09-25

## 目的

在测试存档中验证新版 DLL 与 Copilot 的远征内闭环。每个动作只执行一次；返回 `uncertain` 时先重新读取状态，不重复输入。

## 启动

1. 启动游戏并进入测试存档。
2. 使用 `scripts/start_agent_game.ps1` 注入已部署 DLL。
3. 运行 `npm run copilot:live`。
4. 请求一次 `state`，确认 `revision`、`phase`、`context` 与游戏画面一致。

## 观测验收

- 战斗：双方位置、生命、压力、持续状态、抗性、技能说明均可读。
- 探索：房间物件、地图相邻房间、当前位置和已访问状态一致。
- 背包：`capacity.slotCount`、`capacity.occupiedCount` 与非空物品格一致。
- 光照：数值或特殊环境光名称与画面一致。
- 扎营：餐食消耗/效果、剩余时间和技能说明可读。
- 任务与结算：任务目标、当前按钮和结算页状态可读。

## 动作验收顺序

1. `use_torch`：核对光照增加和火把减少。
2. `move_hero`：核对实际队伍顺序改变。
3. `use_inventory_item`：选择低风险补给，核对数量和目标效果。
4. 房间物件、事件、战利品和多出口路线各完成一次。
5. 有营火的任务中依次验证餐食、一个单体技能、一个全体/自身技能和结束扎营。
6. 在可随时回滚的测试任务中验证 `retreat_combat` 或 `abandon_expedition` 的确认弹窗。
7. 完成任务后验证回城/继续探索和逐页结算。

## 通过条件

- 画面与中间层状态一致；
- 每个成功动作都有游戏状态或日志结算证据；
- 没有连续移动、重复确认、重复消耗或陈旧 revision 输入；
- `get_state(delta)` 不重复返回完整技能/角色快照；
- 关键动作的 `rationale` 出现在 `get_briefing` 中。

城镇长期经营另行验收。公会、铁匠铺、疗养院、减压设施和饰品商店的界面结构不同，需要在各建筑真实打开后分别采集候选和结算证据。
