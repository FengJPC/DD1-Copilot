## 已修复：确认弹窗的信息与回答

新增 `confirmation_dialog_observed` 解析，将 DLL 现有 `confirmpopup ... text="..."` 的完整文字保留为 `activeDialog`。确认窗口的正文直接成为 `decision.prompt`，两项回答的名称与索引进入决策动作；增量事件标记为 critical。关闭或切换上下文后清除旧弹窗，普通状态检查不丢失仍打开的提示。

新增 `choose_dialog_option { optionIndex }`，只允许当前已读出的回答。经 DLL `activate_element` 调用回答元素；元素编号来自本地源码 `CONFIRM_ANSWER_BASE + index`，无需模拟按键或鼠标。若标签格式无法可靠解析，保留完整正文，不生成推测的选项。

实机在原窗口核对成功：

```text
你花费将不会返还，但是英雄将可以立即加入任务。你确定么？ A, 是. B, 否.
optionIndex=0: 是
optionIndex=1: 否
```

选择“否”128 ms，原始日志确认 `fe-activate id=0x636e6662 via native callback rva=0x7bd5a0`，随后返回 building。构建及 12 项相关测试通过，包含完整提示、基线/增量、状态清理、原生动作、去重与过期回答拒绝。无需重新部署 DLL。
