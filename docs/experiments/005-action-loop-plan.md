# M2 动作闭环验证计划

## 目标

证明“发送动作 → 游戏执行 → 运行时日志回执 → 状态归约器确认”的完整闭环，然后再逐步扩大动作范围。

## 分层验证

### A. 可逆界面动作

1. 确认唯一的 `Darkest.exe` 进程和有效主窗口；
2. 把游戏窗口切到前台并再次核对窗口句柄；
3. 发送 F10；
4. 等待日志出现 `settings: opened`；
5. 再发送 F10；
6. 等待日志出现 `settings: closed`。

该步骤不修改存档，可以验证输入注入、窗口焦点和日志回执。

实测结果：Computer Use 键盘输入没有进入 SDL 队列；改用可逆的英雄鼠标选择后，画面与日志均成功确认动作，详见 `006-action-loop-smoke.md`。

### B. 非提交式游戏导航

在安全界面发送单次方向键，验证日志中的焦点或选择项变化。每次只发送一个按键，读取新状态后再决定下一步。

### C. 单英雄战斗回合

1. 观察当前行动者、技能列表和合法目标；
2. 选择一个技能；
3. 等待 `skill_armed` 和目标列表；
4. 选择目标并提交；
5. 等待伤害/状态结算与行动者切换；
6. 必要时用存档快照核对结果。

首轮只执行一个英雄回合，不预先发送整串按键。

## 安全约束

- 输入执行器只接受白名单按键；
- 游戏未运行、存在多个游戏进程、窗口无效或前台核对失败时拒绝发送；
- 一次动作完成并收到明确回执后才发送下一次动作；
- 超时或结果不明确时先重新观察，不重复发送可能已经生效的动作。
