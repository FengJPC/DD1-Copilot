## 本次边界

- 编队 `frontToBack` 是有意的接口变更：名字数组不再有效，必须从候选名单取得 GUID。
- 旧日志缺少 runtime GUID 时，物品/营地单体操作会停止；新的 ID 路径必须搭配本轮 DLL。
- 陷阱/奇物/移动等已有位置语义工作流保留。旧战斗 side/slot 输入仍有按目标预览逐步核对的兼容路径。并非所有底层按键都被删除。
- `skillElementId` 绑定当前行动栏，不能当作跨英雄/跨运行稳定的技能 ID。
- 重复请求缓存限于当前 Copilot 进程及历史容量；原始 Game MCP 仍是底层调试接口，应避免与 Copilot 同时发送输入。
- 本轮没有改存档、安装插件、发布仓库、更改许可或启动游戏。

## 首轮实机复核与修正

`2026-09-26T14:50` 左右的首轮检查中，磁盘上的构建 DLL 与游戏目录 DLL 哈希一致并包含 `runtime_guid` 格式串，但运行中 actor 日志仍是旧格式。这表明该游戏进程实际加载的是部署前映像；本轮不能据此判断新的 GUID getter 是否有效，必须在完整关闭游戏和启动器后冷启动复核。

同一轮 `use_torch` 正确定位到火把第 5 格，游戏日志确认打开了 `itemuse: begin "火把" slot 5 targets=4`。由于旧映像没有提供运行时 GUID，中间层拒绝提交目标，但旧实现只返回恢复建议，未实际退出目标界面。现已修正为：

1. `use_torch` 预检要求已核验的队员运行时 GUID；缺失时不发送任何按键或提交；
2. 若在打开目标界面后仍丢失 ID，发送一次 Escape，并以 `itemuse: abandoned (cancelled)` 或上下文退出作为成功取消证据；
3. 背包第 3 格的两份食物由原始完整快照确认一直存在，不是 `itemuse` 解析污染。
