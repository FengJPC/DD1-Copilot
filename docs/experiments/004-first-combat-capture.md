## 日志字段覆盖

Blindest 调试日志可以直接提供：

- 当前行动英雄、职业、生命和压力；
- 技能内部 ID 与本地化名称；
- 候选目标、敌我位置和范围/单体信息；
- 预计命中率、伤害区间、暴击率和目标当前生命；
- 实际伤害、闪避、眩晕、流血和减益结算；
- 行动者切换、敌人集合变化、教程弹窗和战利品界面切换。

本场日志没有单独输出一条可靠的 `combat ended` 事件，但“敌人集合归零 + 战利品窗口打开”可以作为实时结束候选，随后再用存档中的 `inbattle=false` 和战斗计数确认。

## 存档字段覆盖与延迟

`persist.raid.json` 可以提供：

- `inbattle`、回合数、先攻列表和当前行动索引；
- 敌人的内部类型、当前生命、眩晕、buff 与 DOT；
- 战斗完成计数、战利品结果和背包变化。

以调试日志创建时刻和日志内部毫秒计数对齐，得到近似延迟：

| 事件 | 对应 raid 快照延迟 |
|---|---:|
| 进入战斗 | 0.21 秒 |
| 霰弹轰扫伤害 | 2.90 秒 |
| 晕眩击伤害 | 3.90 秒 |
| 切开血管伤害 | 3.53 秒 |
| 流血击杀/战斗结束 | 3.85 秒 |

因此存档轮询足以承担检查点和结果校验，但不适合单独驱动逐动作战斗决策。

## 采集器修正

游戏会短暂创建 `persist.map.json.stmp` 后再替换正式文件。首轮采集曾在该临时文件消失时产生一次可恢复错误和一个空序号。`capture_live_session.ps1` 已改为只采集以 `.json` 结尾的正式 `persist.*.json` 文件。

## 架构结论

M1 采用双通道只读观察器：

1. Blindest 日志尾读器生成低延迟战斗事件和界面阶段；
2. 存档轮询器生成持久状态快照并校验动作结果；
3. 统一状态层合并两者并标注来源、版本和观测时间；
4. 战斗结束采用“实时候选 + 存档确认”的两阶段判定。
