# 第二轮远征：战利品 revision 与战斗交接稳定性

日期：2026-09-26

## 实机现象

1. 战斗胜利后出现 450 金币和 1 颗黄水晶。背包有未满的金币堆，理论上可以直接收纳金币。
2. `take_all_loot` 与随后按 `itemIndex=0` 的单件拾取都在校验阶段返回 `expected number, received NaN`；没有动作步骤，也没有向游戏发送输入。
3. 修女的群体治疗详情为“目标所有位置”。调用方省略目标时，中间层曾误判为必须指定目标；以修女自身 GUID 作为锚点后才能执行。
4. 一次战斗动作完成后，中间层短暂返回了旧行动者；下一次动作的 revision/行动者校验正确阻止了错误输入，但给模型制造了一次无效决策。
5. revision 增量仍夹带重复的 `skill_observed` 和远征任务观察记录。

## 根因与修复

### 普通动作的 revision

常驻助手的 `act_current` 会读取当前 revision，而普通 `act` 直接执行了 `Number(request.expectedRevision)`。字段省略时得到 `NaN`，严格动作 schema 因而在发送输入前拒绝请求。

现在普通 `act` 在字段省略或为 `null` 时先获取紧凑状态，并将该状态的 revision 作为动作预期版本。显式 revision 仍保留原值并由引擎严格校验。

### 群体技能

无调用方目标判定扩展为：

- `目标无`
- `无需目标`
- `目标所有位置`
- `Target: None`
- `Target: All positions`
- `No target`

这类技能若点击后直接结算，中间层立即核对结果；若游戏仍打开自身目标光标，中间层以当前行动者 GUID 完成确认。

### 战斗交接

候选行动者必须同时满足：

1. `turnTick` 晚于刚完成动作的行动者；
2. 结构化检查的 `actorAddress` 与候选行动者一致；
3. 新技能栏非空；
4. 同一候选稳定至少 150 ms。

回归测试先注入一个带完整技能栏的短暂错误修女快照，10 ms 后再注入真正的雷纳德快照；等待结果必须是雷纳德。

### 增量噪声

英雄档案、等级、远征状态/地点/任务以及技能观察属于结构化快照的组成部分。它们继续更新内部状态，但从模型的逐条增量记录中剔除。
