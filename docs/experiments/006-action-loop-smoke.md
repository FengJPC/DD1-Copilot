# M2 首个动作闭环冒烟测试

> 日期：2026-09-25
> 场景：Old Road 第一战结束后的房间视图
> 操作范围：可逆界面选择，不修改存档

## 目标窗口

Computer Use 返回且仅返回一个目标窗口：

- 应用：`Darkest.exe`；
- 标题：`Darkest Dungeon`；
- 窗口模式：1922 × 1112；
- 初始状态：Reynauld 被选中，队伍 2 人，敌人 0。

## 键盘输入结果

分别尝试发送：

1. F10；
2. 句点键；
3. 点击窗口标题栏重新聚焦后再次发送句点键。

每次都在动作后立即刷新画面并检查 `ddaccess-debug.log`。画面与日志均没有发生对应变化，因此这些按键没有进入 DD1 的 SDL 输入队列。没有重试任何结果不明确的动作。

### 输入法排查

玩家的物理 `A/D` 一度无效。DD1 的 `app.log` 同时出现连续增长的
`event.edit.length`，说明按键被中文输入法的预编辑缓冲区接收。玩家切换到英文输入后，
物理键盘恢复正常。

随后通过 Computer Use 向 DD1 发送 `Win+Space` 和 `Shift+D`。Blindest 日志确认窗口键盘
布局从 `00000804`（中文）切换为 `00000409`（英文），但没有出现 `tilestep` 或任何移动
回执。由此可以区分两个问题：

- 玩家物理键盘失效由中文输入法造成；
- Computer Use 的合成键即使在英文布局下也没有进入 DD1 的 SDL 输入队列。

## 鼠标输入闭环

### 选择 Dismas

1. 从最新截图定位 Dismas 的人物区域；
2. 单击 Dismas；
3. 画面角色面板从 Reynauld 切换为 Dismas；
4. Blindest 日志记录：

```text
heroswap: ... -> Dismas, 强盗. 23/23 生命：. 0/200 压力：.
```

### 恢复 Reynauld

1. 从刷新后的截图定位 Reynauld；
2. 单击 Reynauld；
3. 画面角色面板恢复为 Reynauld；
4. Blindest 日志记录：

```text
heroswap: ... -> Reynauld, 十字军. 33/33 生命：. 0/200 压力：.
```

### 探索移动限制

尝试在画面右侧使用一次和连续十次拖动来模拟“按住鼠标向右走”。光标动作可见，但队伍
位置没有变化。Computer Use 当前只提供单击和短促拖动，无法稳定表达 DD1 探索移动需要的
持续按住状态。

## 结论

已证明以下闭环可用：

```text
截图观察
→ 发送鼠标动作
→ 游戏界面变化
→ Blindest 内存日志回执
→ 状态确认
```

Computer Use 的键盘注入当前不能作为 DD1 动作执行器。鼠标单击足以验证英雄、技能和目标
选择，但不能承担走廊持续移动。下一步可以由玩家手动移动到下一场战斗，再用鼠标坐标完成
一个英雄战斗回合；长期方案仍应通过 Blindest 的内部输入合成模块或结构化 IPC 执行语义
动作，以避免依赖输入法、持续按住、分辨率和画面坐标。
