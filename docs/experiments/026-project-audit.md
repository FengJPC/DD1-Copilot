# 0.2.4 项目审计与自动验证

日期：2026-10-06。用户选择“先完成代码和自动检查”，本轮不启动游戏，不进行实机输入。

## 范围与修复

| 范围 | 问题 | 处理 |
|---|---|---|
| 状态/决策 | 城镇 `1/max` 易被当作当前战斗生命 | 单独标记来源、最大值及当前生命未核实；compact/delta 不返回歧义比值 |
| 英雄档案 | 旧远征生命可能在城镇仍被当作当前生命 | 转入历史字段，城镇与地下城来源分开 |
| 建筑观察 | 缓存 focused hero 可能污染另一个 GUID 的职业/训练 | 名单入口地址与人物地址匹配，身份不明不关联 |
| 饰品操作 | 只有已装备信息，没有可用的双向 ID 事务 | 新增完整仓库快照、GUID/物品 ID 装卸、主线程重查与双侧结果核对 |
| 日志归约 | 半截或失效库存可能保留为可操作事实 | begin 清理、end 数量核对、unavailable 清除；缺失不能放行动作 |
| 观察缓存 | 长时间运行的检查去重集合无容量上限 | 有界缓存，并在日志 generation 改变时重建；持久化动作回执独立 |
| 命令传输 | UTF-8 分包可能破坏中文；连接提前结束仍等超时 | StringDecoder；未收到回执的断连立即报告执行未知；异常 reason 不当作字符串 |
| 构建/部署 | 源码、DLL 和版本容易脱节 | 编译清单记录所有 cpp/h/inc 哈希；部署核对 DLL、路径、完整源码清单，再备份与替换 |
| MCP/插件 | 不同入口版本字符串漂移 | 共同读取包版本；插件两份清单统一 0.2.4 |
| 结构 | 新逻辑继续堆到引擎会扩大维护范围 | 生命投影、档案合并、装备校验/工作流、观察缓存分别独立；引擎只协调 |

未做破坏性 SQLite 迁移；未改变存档独立查询方式、模型决策责任和四类记录边界。依赖 lockfile 只更新项目版本，没有新增公共运行依赖。
